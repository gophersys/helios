## Goal

`go/workspaceprovider/kubernetesadapter` dies at exactly 600s in its integration
lane, because `go/_ctl/lib.sh` runs `go test -tags integration` with NO `-timeout`
and Go's default is 10 minutes per package. Give the substrate lanes a STATED
budget, so a real-cluster suite has room and a hang is still reported.

**It is not sailing past the wall — it is a coin flip at 91-100% of it.** That is

## The shape

One home for the knob, matching `EDEN_COVERAGE_FLOOR`: default in
`go/_ctl/lib.sh`'s metadata block, override in the per-library dispatcher.

- `go/_ctl/lib.sh` — `: "${EDEN_SUBSTRATE_TIMEOUT:=10m}"`, REJECT `0`/`0s`/empty
  with a named error, pass `-timeout` in `cmd_integration`, `cmd_lifecycle`,
  `cmd_load` and `_cover_profile`, add `-v` to `cmd_integration` only, print the
  budget in `lib_usage`.
- `go/workspaceprovider/ctl.sh`, `go/orchestrator/ctl.sh` — `25m` (~1.4x the CI
  estimate).
- `.ci/ci.contract.yaml` — merge tier 30 -> 45 minutes, workflows REGENERATED by
  `cictl generate`, never hand-edited.
- 17 goldens re-recorded, diff reviewed line by line.

The default `10m` is Go's own, so the 14 non-cluster libraries change behaviour
not at all — only the number stops being implied.

## THE RISK THAT EXPLAINS THE WHOLE DEFECT

**A pull request touching only `go/_ctl/lib.sh` runs ZERO library gates.**
`go/_ctl` has no `project.json` and `.ci/ctl.sh` skips it by name, so the
substrate tier would never exercise the fix. The 2 `ctl.sh` overrides MUST land in
the same pull request — that is what makes both libraries affected.

This is exactly how the defect survived, and I saw the same shape on libs #12
hours ago: both tiers green, zero libraries gated.

## Deliberately deferred — the REAL fix

Wire the shared cluster the harness already advertises. `WithPerTest`'s dead
`perTest` field, plus the already-written `uniqueClusterNamespace(t)` and per-test
`reap()`, are the machinery. 8 clusters -> 3 (`K3dClusterWithRegistry` needs
`--registry-config` and cannot share).

It is deferred for a stated reason, not from timidity: it changes a shipped
`<lib>test` package used by 2 libraries, carries real flake risk on the lane that
ALREADY flakes, and **there is no per-test cost measurement in CI to prove it
worked**. The `-v` in this change creates that baseline first.
