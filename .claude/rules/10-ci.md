# CI

Full reference: [docs/ci.md](../../docs/ci.md). The essentials for working here:

## Where it runs

`runs-on: arc-org` — the gophersys org-wide ARC runner scale set on the homelab
k3s cluster, defined in the **infrastructure repo** at
`platform/services/gitops/registry/app-arc-runners-org.yaml` and reconciled by ArgoCD.

Those runners have **no sudo** and a stock runner image, so every tool this project
needs comes from a container, not `apt-get`.

## What "passing" means

`.github/workflows/ci.yml` runs ruff plus the **full** test suite inside the org
category image `ghcr.io/gophersys/hardware`, pinned by digest, which carries KiCad 10.
That means the ERC / DRC / Gerber / netlist tests actually execute — they cannot
execute on a machine without KiCad, where they skip instead.

That image is built in the eden `.devcontainer/` estate, not here. This repo only
consumes it: the pull uses the repo secret `GHCR_PULL_TOKEN` (the package is private
and cross-repo, so `GITHUB_TOKEN` gets a 403), and every `docker run` passes
`--user root` because the image defaults to uid 1000. A failed pull is a hard failure
that names the image — there is no local-rebuild fallback.

**A green local run is weaker than a green CI run.** Before claiming the suite passes,
check the skip count: locally without KiCad roughly 58 tests skip, and those are
precisely the ones covering the pipeline's validation loop.

## Reproducing CI locally

```bash
IMAGE=$(grep -o 'ghcr.io/gophersys/hardware[^ ]*' .github/workflows/ci.yml | head -1)
docker pull "$IMAGE"     # docker login ghcr.io first — the package is private
docker run --rm --user root -v "$PWD":/workspace -w /workspace "$IMAGE" \
  python3 -m pytest tests/ -q
```

The devcontainer has the same KiCad 10, so it works there too.

## Things that will bite you

- **The image is not built here.** `ci/Dockerfile` and `build-ci-image.yml` still exist
  and still publish `ghcr.io/gophersys/research-hardware-ci`, but nothing consumes it —
  it is the rollback anchor only. Editing it changes nothing about CI. Toolchain
  changes belong in eden `.devcontainer/_delta/hardware.sh`, then the digest in
  `ci.yml` is bumped here.
- **`.devcontainer/Dockerfile` still builds its own KiCad** and is now the only place
  that can drift from what CI runs. It is retired in the same follow-up that deletes
  `ci/Dockerfile` (see docs/image-notes.md §5).
- **The pilot corpus is pinned by commit** in `scripts/clone_pilots.sh`. Changing it
  invalidates the CI cache (keyed on that file's hash) — which is intended. Never
  unpin: an unpinned clone tracks upstream HEAD, so someone else's commit can turn
  this repo red overnight. `scripts/check_pilot_pins.sh` enforces this in CI.
- **The org has 4 runner slots total**, shared with every other gophersys repo. CI is
  a single job on purpose; adding jobs costs queue time across the whole org.
