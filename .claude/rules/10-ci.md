# CI

Full reference: [docs/ci.md](../../docs/ci.md). The essentials for working here:

## Where it runs

`runs-on: arc-org` — the gophersys org-wide ARC runner scale set on the homelab
k3s cluster, defined in the **infrastructure repo** at
`platform/services/gitops/registry/app-arc-runners-org.yaml` and reconciled by ArgoCD.

Those runners have **no sudo** and a stock runner image, so every tool this project
needs comes from a container, not `apt-get`.

## What "passing" means

`.github/workflows/ci.yml` runs ruff plus the **full** test suite inside
`ghcr.io/gophersys/hardware-ci`, which carries KiCad 10. That means the ERC / DRC /
Gerber / netlist tests actually execute — they cannot execute on a machine without
KiCad, where they skip instead.

**A green local run is weaker than a green CI run.** Before claiming the suite passes,
check the skip count: locally without KiCad roughly 58 tests skip, and those are
precisely the ones covering the pipeline's validation loop.

## Reproducing CI locally

```bash
docker build -f ci/Dockerfile -t hardware-ci ci/
docker run --rm -v "$PWD":/workspace -w /workspace hardware-ci \
  python3 -m pytest tests/ -q
```

The devcontainer has the same KiCad 10, so it works there too.

## Things that will bite you

- **Two Dockerfiles carry KiCad**: `ci/Dockerfile` and `.devcontainer/Dockerfile`.
  Bump `KICAD_PPA_VERSION` in both, or developers stop reproducing CI.
- **The pilot corpus is pinned by commit** in `scripts/clone_pilots.sh`. Changing it
  invalidates the CI cache (keyed on that file's hash) — which is intended. Never
  unpin: an unpinned clone tracks upstream HEAD, so someone else's commit can turn
  this repo red overnight. `scripts/check_pilot_pins.sh` enforces this in CI.
- **The org has 4 runner slots total**, shared with every other gophersys repo. CI is
  a single job on purpose; adding jobs costs queue time across the whole org.
