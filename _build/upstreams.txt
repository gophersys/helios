# _build/upstreams.txt — where the next value of every pin comes from.
#
# Every pin of the 6 value homes carries exactly 1 row here, and every row names
# a pin that exists. `_ctl/tests/upstream-coverage.test.sh` holds both
# directions, reading the pins out of the HOMES and never out of this table: a
# rule that read the listing would go on reporting coverage after the pin it
# covers was renamed.
#
# The grammar is the grammar of its neighbour _build/download-exemptions.txt —
# 1 table shape in _build/, not 2 — 4 fields, none empty:
#
#   <pin>|<datasource>|<coordinate>|<policy or reason>
#
# The 12 datasources. 11 of them resolve a version from an upstream and are
# driven, 1 stub pin each, by `_ctl/tests/resolve-upstream.test.sh`:
#
#   github-release    the newest release github marks latest, of <owner>/<repo>
#   pypi              info.version of <package> on the index
#   npm               dist-tags.latest of <package> on the registry
#   apt               the newest published binary of <package>@<ubuntu series>
#   go-dl             the newest stable release of the go download index
#   node-dist         the newest LTS release of the node distribution index
#   oci-index         the INDEX digest <repository>:<tag> holds now
#   k8s-dl            the <channel>.txt release channel of dl.k8s.io
#   tailscale-pkgs    the <channel> package index of pkgs.tailscale.com
#   flutter-releases  the <channel> channel of the flutter linux release index
#   eden-manifest     the value gophersys/eden pins in <repo>:<path>
#
# The 12th is `no-autobump`, which resolves nothing. Its 4th field is the REASON,
# and it has to be a sentence: `n/a`, `todo` and `-` all pass a non-empty test,
# and each one is a pin nobody decided about wearing the label of a pin somebody
# did. 13 pins take it today.
#
# The download URL is deliberately NOT here. The resolver reads it out of the
# file that performs the download, because the digest must be of the bytes the
# BUILD fetches; a second URL home lets a correct digest be computed of the
# wrong asset. The `# upstream-published: <url>` comment beside each digest row
# already names the checksum file, and it gets no second home either.
#
# A github-release row rests on the release github marks `latest` being the
# release of the tool this pin names. For a repository that publishes several
# products under one release stream that is not true, and the weekly run then
# FAILS naming the pin when the asset URL 404s. The answer is a corrected row or
# a no-autobump row, decided by a human — never a silent skip.

# The 3 harness versions MUST match gophersys/eden harnesses/versions.env, and
# eden's harness-upgrade-check is the one decision point for them. The
# eden-manifest datasource that mirrors that file needs a read of a PRIVATE
# repository, and this repository's GITHUB_TOKEN is repository-scoped: the read
# needs EDEN_MANIFEST_READ, a fine-grained PAT only Mateo can mint. Until it
# exists these 3 rows say so, and the day it is minted each one becomes

# -------- no-autobump: the pins that are not a version --------
# Each of these selects a MAJOR line or a channel inside a name, so the value an
# upstream would report is not the value the pin spells: python3.13 is a
# different package, openjdk-22-jdk-headless is a different package, and
# resolving stable to a number would freeze the channel this pin exists to
# follow.
PYTHON_PACKAGE|no-autobump|python3.12|the pin is an apt PACKAGE NAME carrying the major line, so the archive version of that package is not what this row holds
JAVA_VERSION|no-autobump|openjdk-21-jdk-headless|the pin is the jdk major line inside an apt package name, so the point release the archive publishes is not what this row holds
RUST_CHANNEL|no-autobump|stable|rustup takes a channel and not a version, and resolving it to a number would freeze the channel this pin exists to follow
FLUTTER_CHANNEL|no-autobump|stable|the flutter download url takes a channel and not a version, and FLUTTER_VERSION is the row that moves
BENCHSTAT_REF|no-autobump|golang.org/x/perf|the module is untagged upstream, so `go install @latest` is the canonical install form and there is no release to compare against

# -------- no-autobump: the android toolchain --------
# The android sdk is published through sdkmanager and dl.google.com, and neither
# offers a machine-readable index of the current build. Giving these 3 an index
# is a later change; today the honest answer is that nothing watches them.
ANDROID_CMDLINE_TOOLS_VERSION|no-autobump|dl.google.com/android/repository|google publishes the cmdline-tools build number in no machine-readable index, so nothing here can read the current one
ANDROID_PLATFORM_VERSION|no-autobump|sdkmanager platforms;android-N|the pin is an android api level chosen by the app target, and sdkmanager publishes no index a resolver can read
ANDROID_BUILDTOOLS_VERSION|no-autobump|sdkmanager build-tools;N|the build-tools version is chosen with the api level above, and sdkmanager publishes no index a resolver can read
