# _build/upstreams.txt — where the next value of every pin comes from.
#
# Every pin of the value homes carries exactly 1 row here, and every row names a
# pin that exists. `_ctl/tests/upstream-coverage.test.sh` holds both directions,
# reading the pins out of the HOMES and never out of this table: a rule that
# read the listing would go on reporting coverage after the pin it covers was
# renamed.
#
# The homes are `PIN_VALUE_HOMES` in `_ctl/lib.sh` — read that list, never a
# count of it here. base/Dockerfile was one of them until its ARGs went
# value-less; every pin it used to declare is a versions.env row now, and the
# row a pin takes here did not move with it, because a row is keyed by the PIN
# NAME and no name changed.
#
# The grammar is the grammar of its neighbour _build/download-exemptions.txt —
# 1 table shape in _build/, not 2 — 4 fields, none empty:
#
#   <pin>|<datasource>|<coordinate>|<policy or reason>
#
# The 13 datasources. 12 of them resolve a version from an upstream and are
# driven, 1 stub pin each, by `_ctl/tests/resolve-upstream.test.sh`:
#
#   github-release    the newest release github marks latest, of <owner>/<repo>
#   pypi              info.version of <package> on the index
#   npm               dist-tags.latest of <package> on the registry
#   go-proxy          .Version of <module>/@latest on proxy.golang.org
#   apt               the newest published binary of <package>@<ubuntu series>
#   go-dl             the newest stable release of the go download index
#   node-dist         the newest LTS release of the node distribution index
#   oci-index         the INDEX digest <repository>:<tag> holds now
#   k8s-dl            the <channel>.txt release channel of dl.k8s.io
#   tailscale-pkgs    the <channel> package index of pkgs.tailscale.com
#   flutter-releases  the <channel> channel of the flutter linux release index
#   eden-manifest     the value gophersys/eden pins in <repo>:<path>
#
# The 13th is `no-autobump`, which resolves nothing. Its 4th field is the REASON,
# and it has to be a sentence: `n/a`, `todo` and `-` all pass a non-empty test,
# and each one is a pin nobody decided about wearing the label of a pin somebody
# did. 15 pins take it today — this sentence read 16 while the file held 13, and
# 14 while it held 15, so read the rows and never this number.
#
# A reason has to be TRUE, and nothing in the pull request gate can check that.
# 3 of these rows were corrected after their reasons were measured against the
# real upstreams: the android index this file said did not exist does, and 2
# github-release coordinates could never have resolved at all. A reason nobody
# measures is the same defect as a pin nobody watches, 1 level up.
#
# The download URL is deliberately NOT here. The resolver reads it out of the
# file that performs the download, because the digest must be of the bytes the
# BUILD fetches; a second URL home lets a correct digest be computed of the
# wrong asset. The `# upstream-published: <url>` comment beside each digest row
# already names the checksum file, and it gets no second home either.
#
# A github-release row rests on the release github marks `latest` being the
# release of the tool this pin names. For a repository that publishes several
# products under one release stream that is not true, and the weekly run then
# FAILS naming the pin when the asset URL 404s. The answer is a corrected row or
# a no-autobump row, decided by a human — never a silent skip.

# -------- go-proxy --------
# The pins a Dockerfile installs with `go install <module>@v${PIN}`. The
# coordinate is the MODULE path and never the package path under it: the proxy
# serves a module, so `github.com/go-delve/delve` and not
# `github.com/go-delve/delve/cmd/dlv`, and a `/v2` suffix is PART of the module
# path rather than decoration.
#
# WHY THESE MOVED OFF `github-release`. A release is a document a human writes
# about a tag; `go install` never reads one. It asks this proxy, so the proxy is
# the upstream that decides the bytes the build gets, and every other row of
# this table already follows that rule — the digest is of what the build
# fetches. GOVULNCHECK_VERSION is what made the difference measurable: its
# github-release row resolved to v1.1.4 for 7 months after golang/vuln stopped
# cutting releases and went on tagging to v1.7.0, and no run ever went red,
# because a resolver that always answers the same thing looks exactly like a
# pin that is current. Read on 2026-08-25, the proxy answers each of these 5
# with the value its pin already holds, so this change moves no version.
#
# THE CLASS IS NOT THE RULE. GREMLINS_VERSION is a `go install` pin that stays
# on `github-release`, because the proxy answers v0.5.1 for it against a v0.6.0
# tag; BENCHSTAT_REF is one that stays on no-autobump, because the proxy answers
# a pseudo-version. Both rows carry the measurement. `resolve_go_proxy` refuses
# a pseudo-version outright rather than pinning a commit nobody chose.
DELVE_VERSION|go-proxy|github.com/go-delve/delve|bump to the version the module proxy serves as latest
GOFUMPT_VERSION|go-proxy|mvdan.cc/gofumpt|bump to the version the module proxy serves as latest
GOLANGCI_LINT_VERSION|go-proxy|github.com/golangci/golangci-lint/v2|bump to the version the module proxy serves as latest, and the /v2 is part of the module path
GOSEC_VERSION|go-proxy|github.com/securego/gosec/v2|bump to the version the module proxy serves as latest, and the /v2 is part of the module path
GOVULNCHECK_VERSION|go-proxy|golang.org/x/vuln|bump to the version the module proxy serves as latest; this pin is the reason the datasource exists, because golang/vuln froze its github releases at v1.1.4 while tagging on to v1.7.0
