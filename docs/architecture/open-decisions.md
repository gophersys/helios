| OD-15 | **OOM-condition discriminator on the kubernetes real Run path** (02 §2, `workspaceprovider` contract §7 Q14). | OD-14 | **Default-deny egress enforcement gap across v1 substrates** (07 §3, `workspaceprovider`). The contract's default-deny-+-declared-allow egress is only PARTIALLY enforced on the v1 substrates, and the `CapabilityManifest` declares the gap truthfully (the conformance suite verifies the enforced part against the real substrate and Skips honestly where absent — never a fake pass). Concretely: **docker** enforces genuine DEFAULT-DENY for a zero-egress (clean-room) workspace via a per-workspace `--internal` network (verified: off-host dial-out is "Network is unreachable") → `CapEgressPolicy=CapPartial`; it CANNOT do default-deny + SELECTIVE allow (an `--internal` bridge is all-or-nothing; per-destination allow needs daemon-level iptables we do not own), so a workspace that declares egress rules runs on the bridge (declared hosts reachable, but so is everything else). **kubernetes (k3d/kind)** ships flannel, which does NOT enforce `NetworkPolicy` → `CapEgressPolicy=CapAbsent`; the adapter installs the derived default-deny `NetworkPolicy` (inert on flannel) and the conformance egress case Skips honestly. Net v1 gap: NO substrate yet enforces default-deny + selective-allow, and the kubernetes path enforces NO egress at all. | options (recommendation first): (a) adopt a NetworkPolicy-enforcing CNI for the central/test kubernetes substrate (Cilium/Calico) so `CapEgressPolicy` becomes `CapFull` there and the suite's real dial-out assertion runs on kubernetes too; (b) move egress enforcement to the broker/dial-out-agent mesh (07 §3 `management` pattern) and treat the substrate NetworkPolicy as defense-in-depth; (c) accept docker-only default-deny for v1 with the gap declared, scheduling real kubernetes enforcement before any non-Mateo tenant runs on the central cluster. Real selective-allow enforcement is future work (07 §3). | before hosted/central multi-tenant exposure |
