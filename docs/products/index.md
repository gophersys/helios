# Products

Top-level object. Everything in Concord — builds, validation, manufacturing — belongs to a product.

## Structure

- **[Hardware](board-revisions.md)** — board family (`ck_boards`), PCB revisions, SoC targets, AppIDs. Each revision is built and validated independently.
- **[Repositories](firmware-repos.md)** — production and manufacturing firmware repos on Bitbucket. Concord watches these for commits and PRs.
- **[Validation stages](stage-config.md)** — up to five, each with trigger rules, signing key, and build recipe. Configured per revision.
- **Manufacturing stages** — production flashing and POST configuration.
- **Assets** — firmware binaries and test packages generated by build runs and validation sessions.

## Flow

Code push → build run → validation → manufacturing. Each step requires the previous one to complete.

## Access

Per-product. Administrators grant access to individual team members. If you don't have access to a product, you don't see it.
