### Backend — Observability API

- **Observability module** (`src/api/v2/observability/`) — REST endpoints for MTIB hardware snapshots: `GET /nodes/{id}/observability` returns live power, GPIO, ADC, UART, and system metrics
- **MtibObservabilityService** (`src/services/mtib_observability.py`) — gRPC client that connects to edge servers and polls `GetSnapshot` with caching and connection management
- **UART WebSocket handler** (`src/api/v2/system/uart.py`) — Socket.IO handler bridging browser WebSocket to gRPC bidirectional UART streams. Uses native OS thread + Queue + green thread pattern for safe gRPC streaming under eventlet. Events: `subscribe_uart`, `unsubscribe_uart`, `uart_data`, `uart_opened`, `uart_error`
- **Router + disconnect wiring** — UART handler registration, cleanup on client disconnect

### Frontend — MTIB Dashboard

- **MTIB list page** (`/mtib`) — Card grid showing all registered MTIBs with status, IP, revision
- **MTIB detail page** (`/mtib/[id]`) — Live hardware monitoring dashboard:
  - **System card** — Compact display with HW revision, server version, uptime, CPU/memory/disk progress bars. Clickable to navigate to K8s node detail
  - **Power card** — "DUT Power" (ch0) and "DUT Charge" (ch1) with voltage, current, power readings in metric boxes with divide-y separators
  - **ADC card** — 4-column grid of AN0–AN7 with 3-decimal voltage readings
  - **GPIO card** — 8-column chip grid showing pin direction (IN/OUT) and value (HIGH/LOW) with color-coded dots
  - **UART terminals** — Collapsible live terminals for uart0 and uart1, subscribing via WebSocket → gRPC bridge. Shows LIVE/Connecting/Error badges, RX/TX byte counts, 500-line buffer with auto-scroll
- **WebSocket service** — Added `subscribeUart()` following `subscribeLogs()` pattern, filters events by port name for multi-port support
- **Component improvements** — Updated select, modal, settings, sidebar, status badge, namespace selector, pod logs, pod terminal, resource YAML dialog components

### MTIB MCP Server (New App)

## Notes

Big productive session. The observability stack is the first time we have real-time hardware visibility from the browser — you can see power rails, GPIO states, ADC voltages, and live UART output all updating in the dashboard without refreshing. The Socket.IO → gRPC UART bridge was the trickiest part because of the eventlet/gRPC threading conflict, but the native thread + queue + green thread pattern from exec.py worked cleanly.

The MCP server is an experiment — it lets you control MTIB hardware through any MCP-compatible client, which could be useful for automated testing workflows or interactive debugging sessions.

Edge server now has proper unit test coverage for every handler, which was overdue. The mock hardware layer makes it easy to test without real hardware attached.
