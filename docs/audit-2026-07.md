# Cluster audit — 2026-07-07

A full audit of the `homelab` k3s cluster, namespace by namespace and pod by pod
(4 parallel read-only agents plus a synthesis). **Overall result: healthy.** Every
pod was Running and Ready, 43 of 43 Prometheus targets were up, and there was no
crashloop, no OOM and no pending pod. Nearly every pod restart traces to a single
reboot of k3s-w-4 at about 2026-07-06 04:38Z, which was harmless.

This document is the backlog of what the audit found. A fixed item is struck
through when it lands. The version upgrades are staged, because they touch
imperative installs from raw manifests — `kubectl apply`, **not** Helm. No Helm
release exists for these components.

> **Update 2026-07-09:** most of this backlog has landed. That includes all 5
> version upgrades (Longhorn, cloudflared, cert-manager, ingress-nginx, MetalLB),
> the cloudflared hardening and its reconciliation into GitOps (PR #81), the
> network isolation of MinIO, and the hardening of cd-proxy, flaresolverr and
> config-backup. The live status is in `docs/debt-register.md` (D9). This document
> stays as the snapshot taken on 2026-07-07.

## Real issues

- **The cert-manager DNS-01 cleanup fails on Cloudflare** —
  `Error 7003 DELETE /zones//dns_records/…` (the zone id is empty). The result is
  orphaned `_acme-challenge` TXT records and repeated error messages. Issuance
  itself works, because every certificate is Ready. Fix the Cloudflare solver of
  the ClusterIssuer (the zone and the token scope).
- **The Tailscale operator** crash-looped at startup with
  `tag:k8s-operator invalid or not permitted (400)`, then recovered. Grant the tag
  to the OAuth client in the tailnet ACL, so the operator survives a restart.
  *(This is a user action in the Tailscale admin console.)*
- **Prowlarr** throws an NPE (`ValidateCategories`) when it re-tests the health
  check on the nightly branch. The effect is cosmetic: the download client IS
  registered (`categories=[]`) and it grabs correctly.

  FIXED: the streaming timeouts are now 1 hour.~~

## Security posture

**Best in the cluster:** workspaces-api is fully hardened and is the template.
Kyverno, the ESO operator, cert-manager, Argo, Grafana, Loki and
kube-state-metrics are all hardened well.

**Justified privilege, no change needed:** Longhorn (storage), gluetun
(NET_ADMIN, VPN), node-exporter (host metrics), zephyr-devbox (privileged, USB),
the metallb speaker (hostNetwork, NET_RAW), and the `ts-*` proxies (privileged —
this is the Tailscale default).

**Gaps worth closing:**
- **bw-serve** (the vault bridge) runs as root. The capabilities are dropped and
  seccomp is applied, but the entrypoint of the image **cannot** run non-root or
  with a read-only root filesystem (verified: it crashloops). Full hardening
  needs a non-root bitwarden-cli image that we build or vendor. *(This image has
  reached its limit.)*
- ~~**cloudflared** (the internet edge) — empty securityContext, root.~~ **DONE**
  — it is hardened (non-root, read-only rootfs, drop ALL, seccomp) and
  reconciled into git as an Argo Application in manual-sync mode (PR #81). It was
  a raw Deployment and was never Helm.
- The baseline drop-ALL and seccomp settings are missing on prometheus, alloy,
  qbittorrent, prowlarr, homepage and the ARC pods. This is low priority, because
  they are tailnet-only and behind NetworkPolicies. (cd-proxy, flaresolverr,
  minio and config-backup have since been hardened.)

## Staged upgrade plan — items 1 to 3 landed ✅

Each step needs a maintenance window, because the installs are imperative raw
manifests.

1. **Longhorn 1.7.2 → 1.12** — it is EOL and the most privileged component.
   Upgrade one minor version at a time (1.7→1.8→…→1.12), and **back up the
   volumes first**. Highest priority and highest risk.
2. **cloudflared → 2026.6.1** — 13 months behind, and it warns about itself. Low
   risk, because it is stateless.
3. **cert-manager 1.16→1.20**, **ingress-nginx 1.12→1.15** and **MetalLB
   0.14→0.16** — moderate risk.
4. **Tempo 2.9 → 3.0** — breaking. Read the migration notes.
5. Tailscale 1.98.4→1.98.8 (a patch) and the observability minor upgrades — low
   priority.
