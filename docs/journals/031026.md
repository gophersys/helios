## What Got Built

### MTIB Server — Critical UART Fix

Fixed the UART stream latency issue that was causing shell lock failures:

- **uart.py** — Changed to drain ALL queued chunks per request instead of one-at-a-time
- **uart_async.py** — New async UART handler for improved throughput
- **streaming.py** — Shared streaming utilities
- This fix enables reliable device re-personalization after firmware flash

### FUOTA Client — Over-the-Air Updates

Complete FUOTA plan management in `libs/python/corekinect/test/validation/fuota_client.py`:

- **upload_cfw()** — Upload CFW firmware packages to CoreCloud
- **create_plan()** — Create multi-stage FUOTA plans
- **assign_device()** — Assign devices to plans with safety checks
- **get_progress()** — Poll FUOTA transfer progress
- **wait_for_stage_complete()** — Block until stage completion
- **execute_fuota_transition()** — High-level helper for complete FUOTA flow

### CFW Generator Library

Built `libs/python/corekinect/firmware/cfw.py`:

- Generate CFW v2 format from signed+encrypted firmware binaries
- Proper header construction (FileVersion, Timestamp, AppId, Flags, Version, ImageLength)
- Track suffix handling (Bench, Engineering, Production, Manufacturing, Debug)
- Flags validation against firmware VersionDevice.h

## Notes

The UART batching fix was critical — without it, the 2-second shell activation window was being missed because UART data arrived too slowly. The fix ensures all queued data is returned immediately.

FUOTA client enables automated firmware update testing as part of the Stage 4 validation flow. The CFW generator ensures proper flags matching between firmware builds and FUOTA plans.

The CI pipeline infrastructure sets the foundation for automated build-and-test on every PR. Build workers run on dedicated nodes with Zephyr toolchains pre-installed.
