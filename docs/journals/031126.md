## What Got Built

### HTTP API Overhaul

Complete restructuring of backend routes and auth system:

- **Permissions migrated** — `Concord.Admin.Catalog.View` → `products:view` format (24 total permissions)
- **Routes restructured** — Now mirror 12 permission modules: products, builds, validation, manufacturing, fixtures, benches, devices, cluster, users, permissions, api-keys, system
- **Inventory module killed** — 18 routes, 5 Prisma models removed
- **Test coverage** — 873 tests (was 434), added CI, ICLE, admin, MTIB, permission enforcement tests
- **WebSocket tests** — New test suite for analyzer, exec, ICLE, log, UART, validation WS endpoints

Key URL changes:
- `/v2/catalog` → `/v2/products`
- `/v2/ci` → `/v2/builds`
- `/v2/kubernetes` → `/v2/cluster`
- `/v2/mtibs` → `/v2/devices/mtibs`
- `/v2/icle` → `/v2/devices/icle`
- `/v2/auth/users` → `/v2/users`

### FUOTA Test Framework

Complete Stage 5 FUOTA test in `apps/validation/alpha/tests/fuota/test_fuota.py`:

- **All 7 valid transitions** — MFG_A→B, MFG_B→A, DEBUG_A→B, DEBUG_B→A, RELEASE_A→B, RELEASE_B→A, MAIN_BASELINE→MERGED
- **936 lines** of comprehensive FUOTA test code
- Each transition is a complete cycle: flash → verify → personalize → upload CFW → create plan → wait → verify

Fixed `pipeline_assets.py`:
- `get_fuota_transitions()` now returns only valid transitions
- Removed invalid cross-variant transitions

### Validation Queue Auto-Trigger

New scheduler in `apps/backend/http-api/src/api/v2/validation/scheduler.py`:

- **_trigger_validation_job()** — Creates K8s job with all bench/pipeline context
- **schedule_queue()** — Triggers jobs immediately after assignment
- Entry status: ASSIGNED → RUNNING with `jobName` stored

Schema changes:
- Added `jobName` field to ValidationQueueEntry
- Added `QueueEntryStatus` enum
- Added `ProductStageConfig` model for per-product stage settings
- Added `CACHED` status to BuildJobStatus

Flow: builds complete → queue entry created → bench assigned → K8s job triggered

## Notes

The HTTP API overhaul was a major refactor affecting 149 files. The new route structure is much cleaner — routes now directly map to permission modules, making RBAC intuitive.

FUOTA test framework enables automated testing of all firmware update paths. Combined with the queue auto-trigger, the system can now run validation tests end-to-end without manual intervention.

The queue scheduler bridges the gap between CI builds and hardware validation — when a build completes and gets assigned to a bench, the K8s job starts automatically.
