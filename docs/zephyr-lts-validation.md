## 3. Parser-target validation (ESP32-S3)

### 3a. Pinctrl header — `zephyr/include/zephyr/dt-bindings/pinctrl/esp32s3-pinctrl.h`

Autogenerated (`esp_genpinctrl.py`). 4185 `ESP32_PINMUX` entries in the S3 header
(esp32: 3796, s2: 2505, c3: 726, c6: 648). Five extracted signal→GPIO mappings:

```c
#define I2C0_SDA_GPIO2 \
	ESP32_PINMUX(2, ESP_I2CEXT0_SDA_IN, ESP_I2CEXT0_SDA_OUT)
#define LEDC_CH0_GPIO8 \
	ESP32_PINMUX(8, ESP_NOSIG, ESP_LEDC_LS_SIG_OUT0)
#define SPIM2_MISO_GPIO13 \
	ESP32_PINMUX(13, ESP_FSPIQ_IN, ESP_NOSIG)
#define TWAI_TX_GPIO5 \
	ESP32_PINMUX(5, ESP_NOSIG, ESP_TWAI_TX)
#define UART0_TX_GPIO43 \
	ESP32_PINMUX(43, ESP_NOSIG, ESP_U0TXD_OUT)
```

**Format surprises vs. the expected patterns:**

- Expected `ESP32S3_PINMUX` — actual macro is **`ESP32_PINMUX(pin, sig_in, sig_out)`** for *all* SoCs (defined once in `esp-pinctrl-common.h`; packs pin[5:0], sig_i[14:6], sig_o[23:15]). There is no per-SoC macro name; SoC identity comes only from the header filename.
- Expected `#define <PERIPH>_<SIGNAL>_GPIO<N> <n>` — actual defines are **`<SIGNAL-GROUP>_GPIO<N>`** (e.g. `I2C0_SCL_GPIO0`, `MCPWM0_OUT0A_GPIO4`) and expand to an `ESP32_PINMUX(...)` expression, **not a bare number**. Parser must capture the three macro arguments (GPIO number + in/out signal names), and defines are line-continued (`\` then the expansion on the next line) — regexes must join continuation lines.
- Direction is encoded per-entry: input-only signals use `ESP_NOSIG` for the out slot and vice versa (`ESP_NOSIG == ESP_SIG_INVAL == 0x1FF`).
- Signal IDs resolve via the companion **`esp32s3-gpio-sigmap.h`** (`#define ESP_<SIGNAL>_IN/_OUT <id>`, e.g. `ESP_U0TXD_OUT 12`, `ESP_SPIQ_IN 0`) — plain numeric defines, easy to parse.

### 3b. Devicetree — `zephyr/dts/xtensa/espressif/esp32s3/esp32s3_common.dtsi`

- GPIO: two banks under a `gpio` wrapper node — `gpio0: gpio@60004000` with `ngpios = <32>; /* 0..31 */` and `gpio1: gpio@60004800` with `ngpios = <22>; /* 32..53 */` (total 54 pin numbers), both `compatible = "espressif,esp32-gpio"`. Note the wrapper uses `gpio-map` indirection; per-variant dtsi files (`esp32s3_wroom_*.dtsi`, `_mini_`, `_pico_`, etc.) layer on the common file.
- Peripheral nodes found (labels): uart0/1/2, usb_serial (uart@60038000), i2c0/1, spi2/3, twai (node name `can@6002b000` — parser should not assume node name == function), ledc0, mcpwm0/1, pcnt, adc0/1, touch, timer0-3, wdt0/1, xt_wdt, rtc, rtc_timer, trng0, dma, coretemp, ipm0, flash/flash0, psram0, intc, sram0.

### 3c. HAL — `hal_espressif/components/soc/esp32s3/include/soc/io_mux_reg.h`

Pattern `#define FUNC_GPIO<N>_<FUNCTION> <fn-index>`. Three examples:

```c
#define FUNC_GPIO9_FSPIHD                           4
#define FUNC_GPIO12_FSPICLK                         4
#define FUNC_GPIO0_GPIO0                            1
```

Surprise: each pin also has a duplicate zero-index alias suffixed `_0` (e.g. `FUNC_GPIO0_GPIO0_0  0`) — dedupe when parsing. `io_mux_reg.h` confirmed present for all six target SoCs (incl. esp32h2) in the pinned HAL.

## 4. Conclusions

- All three parser targets (pinctrl header, dtsi, HAL io_mux) are present and machine-parseable at v3.7.2 for esp32/s2/s3/c3/c6.
- esp32h2 requires the fallback tag `v4.4.1` for Zephyr-side files only; HAL side is already covered by the pinned revision.
- Parser adjustments needed: single shared `ESP32_PINMUX` macro (not per-SoC), line-continued defines, `ESP_NOSIG` direction sentinel, sigmap companion header for signal IDs, `FUNC_*_0` aliases in HAL, and dual GPIO banks with a `gpio-map` wrapper in the dtsi.
