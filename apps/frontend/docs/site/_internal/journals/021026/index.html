Development Journal — 02.10.26¶

Summary¶

Major restructuring day. Replaced the flat products module with a hierarchical catalog data model (Chipset → Product → Board → BoardRevision → FirmwareBuild), moved Kubernetes pages out of /system into their own route, consolidated permission sets into the users page, and did a full security/code-quality sweep across the HTTP API backend. Also tweaked the Alpha firmware's vitals monitoring output.

What Got Built¶

Catalog Data Model Restructuring¶

The old flat products module had everything in one table. Replaced it with a proper hierarchy:

  • Chipset — standalone entity (e.g., nRF52840, nRF9151), has isModem flag
  • Product — top-level product (e.g., Alpha B0), references chipsets via boards
  • Board — named board within a product (e.g., "Main Board"), scoped per product
  • BoardRevision — versioned revision of a board, many-to-many with chipsets, carries selectedBuilds JSON for firmware mapping
  • FirmwareBuild — per-product per-chipset firmware binary with MinIO storage, optional modem file support

Backend changes: - New catalog/ API module with 6 handler files: chipsets.py, products.py, boards.py, board_revisions.py, firmware_builds.py, firmware_apps.py - New catalog/types.py with request dataclasses for all entities - New catalog/shared.py with validate_product_exists() helper - Updated router, permissions (ADMIN_CATALOG_*), and OpenAPI docs - Deleted entire products/ module (7 files)

Frontend changes: - New catalog/ component directory with board-list.svelte, board-revision-list.svelte, chipset-management.svelte, chipset-tag-input.svelte, firmware-app-list.svelte, firmware-build-upload.svelte, product-card.svelte, product-detail.svelte - New /catalog route page - Deleted entire products/ component directory and route - Updated use-chipsets.svelte.ts hook (replaced use-chipset-config) - Updated sidebar navigation, auth tests, type models

Test coverage: - 6 new test files under tests/api/catalog/ including test_catalog_workflows.py for cross-entity constraint tests - Updated test_product_types.py, test_auth_bypass.py, test_decorators.py for catalog permissions - Deleted old tests/api/products/ (4 files)

Frontend Reorganization¶

  • Kubernetes pages: Moved all /system/* routes to /kubernetes/* with a dedicated layout and Kubernetes icon component
  • Permission sets: Consolidated from standalone /permission-sets route into a tab on the /users page via new permission-sets-tab.svelte component
  • Removed: /guides page (unused)
  • UI polish: Added ARIA labels to search inputs, dialog overlays, upload dropzones across modal, confirm-delete-dialog, artifact-upload, image-upload, settings-modal, resource-yaml-dialog
  • Page tweaks: Minor cleanup across history, codebases, fixtures, mtib, results, statistics, tests pages (removed redundant $effect tracking vars, design token consistency)

Backend Security & Code Quality Hardening¶

Full sweep across all 12 API modules:

  • Security: Added secure_filename() from Werkzeug to sanitize user-uploaded filenames before use as MinIO storage keys in firmware_builds.py and codebases/artifacts.py
  • Validation: Fixed bool() coercion → isinstance(active, bool) check in auth/types.py, reject empty names after .strip(), added .strip() to all string inputs in auth and MTIB request types, sanitized permission list entries with isinstance + .strip()
  • Consistency: Standardized error messages to "Request body must contain JSON data" across 5 request types, fixed admin history response key from "entries" to "data", added Json() wrapper for metadata in node redeployment
  • Logging: Added logger = logging.getLogger(__name__) to 9 handler files that were missing it
  • Cleanup: Removed unused List import from catalog/types.py, removed unused internal_error import from auth/login.py

Firmware¶

  • Consolidated heart rate + SpO2 logging into a single-line format with motion count for easier field debugging
  • Lowered motion detection threshold from 200mg to 100mg for better sensitivity
  • Track g_monitoring_active and g_motion_count as globals for cross-thread visibility
  • Cleaned up state transition log messages (active monitoring, skin lost)

Notes¶

The catalog restructuring was the bulk of the work — getting the data model right for how boards relate to chipsets via revisions, and how firmware builds are scoped per product + chipset, took some thought. The many-to-many between BoardRevision and Chipset via a join table (BoardRevisionChipset) is cleaner than the old approach of embedding chipset references in JSON fields.

The security sweep caught two real issues: unsanitized filenames going straight into MinIO storage keys (path traversal risk) and bool coercion via bool() which would accept any truthy value as True. Both fixed now.

319 backend tests passing after all changes.
