Development Journal — 02.06.26¶

Summary¶

Low-energy day. Didn't commit anything but spent the time on a big MTIB v2 refactor — broke the monolithic server and client into per-domain handler/client modules, added a proper types package for the client, cleaned up legacy handlers, and started on three new backend API modules (Fixtures, Nodes, Deployments). Also got some MTIB tests going. Nothing committed, all WIP.

What Got Worked On¶

MTIB Server v2 — Handler Refactor¶

Ripped out the old monolithic handler structure and broke it into 13 new domain-specific handlers:

Handler Lines Purpose
ble.py 257 BLE scanning, connections, characteristics
can.py 112 CAN bus send/receive/filter
debug.py 306 J-Link debug probe, breakpoints, memory
files.py 182 Target filesystem read/write/list
flash.py 137 Firmware flash/verify/erase
i2c.py 87 I2C scan/read/write
logic.py 114 Logic analyzer capture/decode
rtt.py 89 RTT channel read/write
spi.py 67 SPI transfer/config
swo.py 62 SWO trace capture
system.py 74 System info, self-test
target.py 136 Target power/reset/identify
zephyr.py 143 Zephyr shell, logging, firmware info

Deleted 4 old handlers that were replaced by the new structure: - adc.py (227 lines) — folded into other handlers - firmware.py (636 lines) — split into flash.py + debug.py + files.py - motion.py (219 lines) — removed (not on REV 1.1) - sensors.py (235 lines) — folded into i2c.py and domain handlers

Rewrote gpio.py, power.py, and uart.py to match the new handler pattern. Refactored mtib.py provider to wire up all the new handlers.

Backend API — New Modules (Started)¶

Started three new API modules, none wired up yet:

  • Fixtures (src/api/v2/fixtures/) — CRUD for test fixtures and fixture slots (366 + 145 lines)
  • Nodes (src/api/v2/nodes/) — CRUD for edge nodes / MTIBs (345 + 110 lines)
  • Deployments (src/api/v2/deployments/) — MTIB server deployment management with K8s integration (371 + 29 lines)
  • K8s deployment service (src/services/kubernetes/mtib_deployments.py) — Deploy/teardown MTIB server pods (153 lines)
  • Deployment template (assets/templates/mtib_server_deployment.yaml) — K8s manifest template (101 lines)

Schema & Misc¶

  • 2 new Prisma migrations (0002_update_inventory_categories, 0003_add_fixture_deployment_link)
  • Minor fixes to inventory types, permissions, OpenAPI docs
  • Updated inventory component tests

Notes¶

Didn't really feel like working but the MTIB refactor needed to happen — the old monolithic handlers were getting unmanageable. Breaking everything into per-domain modules makes it way easier to implement each protocol area independently. The client types package is a nice side effect too, gives proper type safety instead of raw protobuf objects everywhere.

Backend modules are just scaffolded, not registered in the router yet. Need to wire those up and add tests.
